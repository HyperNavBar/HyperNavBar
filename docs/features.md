# 功能说明

本文档详细介绍 HyperNavBar「功能」标签页中各开关的具体作用与效果。

<br>

## 规则生效的整体链路

HyperNavBar 不再改写系统规则文件，而是通过 LSPosed Hook 在运行期接管导航栏沉浸规则：

1. 在「规则」页点击 **立即应用**：合并订阅 / 本地规则；
2. 合并结果按包名写入跨进程配置（LSPosed 远程偏好）；
3. system_server 侧 Hook 读取模块规则，**覆盖合并**到系统官方规则之上（模块优先）；
4. 应用进程侧 Hook 在满足开关条件时，绕过官方门槛并执行规则。

因此规则生效不再需要 Root；Root 仅用于批量重启应用与清空 DexKit 缓存。

> **生效时机**：规则在目标应用进程初始化时读取，修改后需重启目标应用。可在功能页 / 作用域页右上角批量「重启」。

<br>

## 系统版本要求

**本模块的全部 Hook 仅适配 HyperOS 4.0 及以上**（手机 / 平板通用）。

- 所有 NBI 相关 Hook 共用同一个版本门禁：`hyperOs >= 4.0`。
- 门禁命中时的行为是**主动跳过**（不安装、不计入失败），因此在 HyperOS 3.x / 2.x、MIUI、Android 原生系统上，模块**不会产生任何 Hook 行为**，只保留规则数据的解析与编辑能力。
- 这组 Hook 依赖的类（`com.android.nbi.*`、`com.android.internal.policy.NavigationBarImmersiveController` / `MiuiNBIManagerImpl` / `DecorViewImmersiveImpl`）为 HyperOS 4 专属，旧系统上并不存在。

> 版本识别来自系统属性 `ro.mi.os.version.name`（如 `OS4.0`）。比较时会去掉 `OS` 前缀归一化为数字版本（`4.0`），因此门禁写作 `hyperOs { ge("4.0") }` 即可正确区分 `OS4.0` 与 `OS3.3`。

**唯一例外**：「旧版残留还原 / 清理」不设门禁。它只做文件层面的 `.bak` 还原与标记删除，不依赖任何 HyperOS 4 专属类，在旧系统上同样安全有效，用于把曾被旧版模块覆盖的规则文件恢复为官方状态。

<br>

## 强制生效

官方代码在满足一系列条件后才会执行沉浸规则。这一组开关就是把这些「跳过执行」的条件逐个拆掉，让模块规则在原本不生效的场景里真正跑起来。

「强制生效」是总开关：只有它开启后，下面的子项才会安装对应的 Hook。默认关闭，对系统零影响。

### 强制生效（总开关）

- **作用**：安装应用进程侧的框架 Hook。
- **关闭时**：只有「规则注入」在工作——规则内容已经覆盖官方，但官方仍按自己的门槛决定哪些窗口 / 应用执行，表现为「规则对了，但很多场景依然不沉浸」。
- **开启后**：下面各子项开始生效，原本被官方跳过的场景会按模块规则沉浸。

### 忽略版本阈值

- **官方限制**：应用版本 `≤ disableVersionCode` 时，系统直接禁用该应用的 NBI。
- **开启效果**：应用升级 / 降级后规则**继续生效**，不再被版本阈值拦住。
- **典型表现**：应用更新后适配莫名失效，开启后恢复。
- **适合**：应用更新频繁、或想对旧版本应用强制套用规则的场景。

### 绕过强制边到边

- **官方限制**：应用自己声明接管 edge-to-edge（`mEdgeToEdgeEnforced`）时，官方整套沉浸逻辑被直接跳过。
- **开启效果**：**自带导航栏样式、对系统适配完全免疫的应用也能被适配**（填色 / 取色 / 悬浮等）。
- **典型表现**：某些应用导航栏永远是它自己的样子，系统怎么调都不变，开启后开始按规则变色。
- **适合**：自带导航栏适配的应用。

### 绕过虚拟显示限制

- **官方限制**：投屏、车机、屏幕镜像等「虚拟显示」场景，沉浸被一律跳过。
- **开启效果**：这些画面也按规则变色 / 沉浸。
- **典型表现**：车机地图、投屏画面上的导航栏开始跟随规则。
- **适合**：车机、投屏、副屏用户；普通手机日常基本用不到。

### 强制手势导航

- **官方限制**：官方要求「手势导航开启」且「手势线未隐藏」才执行沉浸；三键导航或隐藏手势线时整套 NBI 不启动。
- **开启效果**：不论导航方式，都按「手势导航 + 手势线显示」处理。
- **典型表现**：
  - 三键导航用户：原本完全无效果，开启后开始取色沉浸；
  - 隐藏手势线用户：原本被跳过，开启后恢复执行。
- **适合**：坚持用三键导航、或习惯隐藏手势线的用户。注意三键下导航栏是实体条，取色类观感与手势线不同。

### 强制全屏语义

- **官方限制**：非全屏窗口（`windowingMode != 1`）会跳过沉浸决策；SF 采样回调 `handleSFColorCollected` 也会因 `windowingMode != 1` 丢弃实时颜色；且官方 SF 采样区域按「窗口从屏幕左上角开始」计算，分屏 / 小窗下会采到窗口外的背景区域；另外框架仅在 `shouldNotifyDrawForImmersive` 时触发一次决策，内容变化不会自动刷新。
- **开启效果**：分屏、悬浮窗、部分非全屏 Activity / 对话框也进入沉浸决策；**分屏 / 小窗下自动改用窗口视图采样，并为窗口注册每帧监听持续取色**，因此滑动内容、切换页面时小白条颜色都会实时刷新，也不会取到背景颜色；全屏场景保持官方 SF 采样。
- **典型表现**：分屏、小窗里的页面导航栏开始跟随规则，且底部颜色变化时能实时取色。
- **适合**：分屏 / 小窗重度用户。
- **注意**：侵入性较强，若分屏 / 小窗出现导航栏颜色异常，建议优先关闭本项。

### 忽略导航栏隐藏

- **官方限制**：页面隐藏导航栏（`isNavBarHidden()`）时直接跳过。
- **开启效果**：隐藏导航栏的页面也照样执行适配逻辑。
- **典型表现**：全屏视频、全屏游戏、隐藏导航栏的页面也会按规则处理导航栏颜色。
- **注意**：侵入性较强，全屏场景观感异常时可优先关闭本项。

### 组合效果举例

- 只开「强制生效」+「强制手势导航」：三键 / 隐藏手势线的用户也能获得取色沉浸；
- 再加「绕过强制边到边」：连自带导航栏样式的应用也能被模块规则接管；
- 全部开启：覆盖面最大，但副作用概率也最高。

## 规则注入

规则注入为模块核心机制，**默认自动启用，不提供界面开关**。

### 模块规则覆盖合并

- **自动启用**。
- **作用**：system_server 侧 Hook 在系统返回规则时，用模块规则按活动覆盖合并（模块优先），并强制启用、清空版本阈值。
- **意义**：这是「模块规则覆盖官方 cloudFeature」的核心，**不改写任何系统文件、不需要 Root**；未配置到的应用 / 活动自动沿用官方规则。

### 自动还原官方规则文件

- **自动启用**。
- **作用**：旧版本 HyperNavBar 会直接覆盖系统规则文件并留下 `.bak`。此机制在 system_server 启动早期把 `.bak` 还原回目标文件、删除 `.bak` 与标记文件，让系统磁盘恢复为官方状态。
- **意义**：由于运行时由 Hook 注入规则，卸载模块后系统会**自动回到官方规则**，无需残留还原逻辑。

### 排除 Hook（hookExcluded）

- 模块格式规则支持在应用级别添加 `hookExcluded: true`：
  - 应用规则时把该应用从 LSPosed 作用域移除，**不再注入模块**；
  - 其下的 `activityRules` 不生效。
- 用途：部分应用会检测 Xposed 注入并主动退出（即使不安装任何 Hook 也会崩，安全模式也无法避免），这类应用只能用此字段或作用域页「排除」按钮移出注入范围。
- 可视化编辑器在应用编辑面板中提供「排除 Hook」开关。

<br>

## 模块

### 作用域

- 查看已被模块 Hook 的应用（图标 / 名称 / 版本 / 包名）。
- 对目标应用批量「重启」，使规则改动生效。
- 规则只对作用域内的应用生效；功能页开关首次开启时会自动为相关目标申请作用域。

### 安全模式

- **保护机制**：目标应用在加载 Hook 后短时间内反复崩溃时，自动跳过该应用的**全部 Hook**，避免系统应用反复崩溃导致无法开机。
- **手动控制**：可逐应用开关；关闭时恢复并清空崩溃计数。
- 关键应用（系统框架、系统界面、桌面、设置等）阈值更低，优先保护。

<br>

## 副作用与建议

- 「强制全屏语义」「忽略导航栏隐藏」侵入性最强，遇到分屏 / 全屏视频 / 游戏画面异常时优先关闭。
- 强制生效为**全局行为**，不区分单个应用；精细控制仍以「规则」页中针对具体应用 / 活动配置的 `style` 为主，强制生效只负责「让这些规则不被官方门槛拦住」。
- 修改任意开关或规则后，请**重启目标应用**再验证效果。
