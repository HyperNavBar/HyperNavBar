# 功能说明

本文档详细介绍 HyperNavBar「功能」标签页中各开关的具体作用与效果。

<br>

## 规则生效的整体链路

HyperOS 4.x 通过 LSPosed Hook 在运行期接管导航栏沉浸规则；HyperOS 3.3（3.0.3XX）自 3.1.0 起改回以 Root 替换系统规则文件的方式（与 2.x 一致）：

1. 在「规则」页点击 **立即应用**：合并订阅 / 本地规则；
2. **HyperOS 4.x**：合并结果按包名写入跨进程配置（LSPosed 远程偏好），system_server 侧 Hook 读取模块规则，**覆盖合并**到系统官方规则之上（模块优先）；规则由此下发，**无需把第三方应用加入 LSPosed 作用域**；
3. **HyperOS 3.3（3.0.3XX）**：以 Root 读取当前官方规则为基底，合并模块规则后写回 `/data/system/cloudFeature_navigation_bar_immersive_rules_list.json` 并触发系统重载（首次写入前保留 `.bak` 备份）；规则注入 Hook 在 3.3 上不安装；
4. 应用进程侧 Hook（`强制生效` 系列 / 非全屏取色）**默认不注入第三方应用**，需要时可在 LSPosed / 作用域页手动加入。

因此 HyperOS 4.x 上规则生效不需要 Root；**HyperOS 3.3 上应用规则需要 Root**（4.x 的 Root 仅用于批量重启应用与清空 DexKit 缓存）。

> **生效时机**：规则由 system_server 读取并下发生效；修改后如未立即生效，可重启目标应用。可在功能页 / 作用域页右上角批量「重启」。

<br>

## 系统版本要求

**本模块的 Hook 仅适配 HyperOS 3.3（3.0.3XX）及以上**（手机 / 平板通用）。

- 「强制生效」系列等 Hook 共用版本门禁 `hyperOs >= 3.0.3`（3.3 / 4.x）。
- 规则注入 Hook 与「旧版残留还原 / 清理」自 3.1.0 起仅作用于 **HyperOS 4.x**：3.3 改回以 Root 替换系统规则文件的方式挂载规则，写入的文件即为生效数据（因此 3.3 上不做还原）。
- 门禁命中时的行为是**主动跳过**（不安装、不计入失败），因此在更早的 HyperOS 3.0 / 2.x、MIUI、Android 原生系统上，模块**不会产生任何 Hook 行为**，只保留规则数据的解析与编辑能力。
- 这组 Hook 依赖的类（`com.android.nbi.*`、`com.android.internal.policy.NavigationBarImmersiveController` / `MiuiNBIManagerImpl` / `DecorViewImmersiveImpl`）在 HyperOS 3.3 与 4.0 上均存在且结构基本一致，少数差异以版本分支（`HookVariant`）适配（如手势导航判定所在类）。

> 版本识别来自系统属性 `ro.mi.os.version.name`。比较时会去掉 `OS` 前缀归一化为数字版本，门禁写作 `hyperOs { ge("3.0.3") }` 可同时兼容 `OS3.3` 与 `OS3.0.3XX` 两种写法。

**补充**：「旧版残留还原 / 清理」只做文件层面的 `.bak` 还原与标记删除，不依赖任何 NBI 专属类；自 3.1.0 起随规则注入 Hook 一并仅在 4.x 运行，用于把曾被旧版模块覆盖的规则文件恢复为官方状态（3.3 上由模块 App 直接管理规则文件，不做还原）。

## 强制生效

官方代码在满足一系列条件后才会执行沉浸规则。这一组开关就是把这些「跳过执行」的条件逐个拆掉，让模块规则在原本不生效的场景里真正跑起来。

「强制生效」是总开关：只有它开启后，下面的子项才会安装对应的 Hook。默认关闭，对系统零影响。

### 强制生效（总开关）

- **作用**：安装应用进程侧的框架 Hook。
- **关闭时**：只有「规则注入」在工作——规则内容已经覆盖官方，但官方仍按自己的门槛决定哪些窗口 / 应用执行，表现为「规则对了，但很多场景依然不沉浸」。
- **开启后**：下面各子项开始生效，原本被官方跳过的场景会按模块规则沉浸。

### 忽略版本阈值

- **官方限制**：应用版本 `≤ disableVersionCode` 时，系统直接禁用该应用的 NBI。
- **开启效果**：应用升级 / 降级后规则**继续生效**，不再被版本阈值拦住。
- **典型表现**：应用更新后适配莫名失效，开启后恢复。
- **适合**：应用更新频繁、或想对旧版本应用强制套用规则的场景。

### 绕过强制边到边

- **官方限制**：应用自己声明接管 edge-to-edge（`mEdgeToEdgeEnforced`）时，官方整套沉浸逻辑被直接跳过。
- **开启效果**：**自带导航栏样式、对系统适配完全免疫的应用也能被适配**（填色 / 取色 / 悬浮等）。
- **典型表现**：某些应用导航栏永远是它自己的样子，系统怎么调都不变，开启后开始按规则变色。
- **适合**：自带导航栏适配的应用。

### 绕过虚拟显示限制

- **官方限制**：投屏、车机、屏幕镜像等「虚拟显示」场景，沉浸被一律跳过。
- **开启效果**：这些画面也按规则变色 / 沉浸。
- **典型表现**：车机地图、投屏画面上的导航栏开始跟随规则。
- **适合**：车机、投屏、副屏用户；普通手机日常基本用不到。

### 强制手势导航

- **官方限制**：官方要求「手势导航开启」且「手势线未隐藏」才执行沉浸；三键导航或隐藏手势线时整套 NBI 不启动。
- **开启效果**：不论导航方式，都按「手势导航 + 手势线显示」处理。
- **典型表现**：
  - 三键导航用户：原本完全无效果，开启后开始取色沉浸；
  - 隐藏手势线用户：原本被跳过，开启后恢复执行。
- **适合**：坚持用三键导航、或习惯隐藏手势线的用户。注意三键下导航栏是实体条，取色类观感与手势线不同。

### 强制全屏语义

- **官方限制**：非全屏窗口（`windowingMode != 1`）会跳过沉浸决策；SF 采样回调 `handleSFColorCollected` 也会因 `windowingMode != 1` 丢弃实时颜色；且官方 SF 采样区域按「窗口从屏幕左上角开始」计算，分屏 / 小窗下会采到窗口外的背景区域；另外框架仅在 `shouldNotifyDrawForImmersive` 时触发一次决策，内容变化不会自动刷新。
- **开启效果**：分屏、悬浮窗、部分非全屏 Activity / 对话框也进入沉浸决策；**非全屏下仅采样取色类规则（`style=sf` / `view` / 默认）改用窗口视图采样并注册每帧监听持续取色，自定义颜色 / 悬浮（强制沉浸）/ 禁用维持原样**，因此滑动内容、切换页面时小白条颜色都会实时刷新，也不会取到背景颜色；全屏场景保持官方 SF 采样。
- **典型表现**：分屏、小窗里的页面导航栏开始跟随规则，且底部颜色变化时能实时取色。
- **适合**：分屏 / 小窗重度用户。
- **注意**：侵入性较强，若分屏 / 小窗出现导航栏颜色异常，建议优先关闭本项。

### 忽略导航栏隐藏

- **官方限制**：页面隐藏导航栏（`isNavBarHidden()`）时直接跳过。
- **开启效果**：隐藏导航栏的页面也照样执行适配逻辑。
- **典型表现**：全屏视频、全屏游戏、隐藏导航栏的页面也会按规则处理导航栏颜色。
- **注意**：侵入性较强，全屏场景观感异常时可优先关闭本项。

### 组合效果举例

- 只开「强制生效」+「强制手势导航」：三键 / 隐藏手势线的用户也能获得取色沉浸；
- 再加「绕过强制边到边」：连自带导航栏样式的应用也能被模块规则接管；
- 全部开启：覆盖面最大，但副作用概率也最高。

## 手势提示线（小白条）

「手势提示线」分组在 SystemUI 进程内控制小白条（手势提示线）的显示，与沉浸规则相互独立（参考 [HyperModifier](https://github.com/AritxOnly/HyperModifier) 的实现思路）。

### 三种状态（精度到应用）

| 状态 | 表现 |
|---|---|
| **始终显示** | 一直显示 |
| **3 秒后自动隐藏** | 应用切到前台时显示，3 秒后淡出隐藏 |
| **始终隐藏** | 一直隐藏 |

- 规则格式：应用级 `navBarVisibility`（`default` / `alwaysShow` / `autoHide` / `alwaysHide`，默认 `default`，规则没有时自动显式补全）。
- `default` = 跟随功能页的「全局默认适配模式」。
- 可视化编辑器在应用编辑面板中提供「小白条状态」下拉（跟随默认 / 始终显示 / 3 秒后自动隐藏 / 始终隐藏）。

### 设置项

- **手势提示线**（总开关）：安装 SystemUI 侧 Hook；**开启后需重启系统界面（或重启设备）生效**，并会自动申请系统界面作用域；功能页右上角提供「重启」入口——点开后是与作用域页一致的重启弹窗，勾选「系统界面」重启即可（需要 Root）。
- **滑动跟随动画**：拖动底部手势时小白条跟随手指平移，松手后阻尼回弹；只影响绘制（Canvas 平移），不消费 / 修改输入事件。开启后可在下方用滑条调节：
  - **回弹延迟**（0–800ms，默认 260ms）：松手后停留在跟随位置的时间，之后开始回弹；
  - **跟随幅度**（0–100%，默认 50%）：小白条位移相对手指位移的比例；
  - **跟随范围**（0–48dp，默认 24dp）：单方向最大位移上限（同时受小白条到宿主边缘的距离限制）；
  - **回弹速度**（50–200%，默认 100%）：回中动画的速度倍率。
- **触摸唤醒**：触摸底部手势区域（含小白条本身）时临时显示小白条，3 秒后再次隐藏；解锁屏幕时也会重新显示。
- **全局默认适配模式**：规则之外的应用（以及值为 `default` 的规则项）使用的模式。
- **是否优先跟随规则**：
  - **跟随规则**（默认）：先考虑规则——优先使用规则中的应用模式，规则未覆盖的应用回落到全局默认模式；
  - **不跟随规则**：忽略规则，所有应用统一使用全局默认模式。
- 官方「隐藏手势提示线」开启时，模块会按需保活提示线宿主，使规则仍然生效（不改写系统设置与导航方式）。

> 显隐切换带 220ms 渐变（触摸 / 滑动唤醒为 90ms 快速显示）；Hook 仅安装在 SystemUI 进程，低版本系统会自动跳过。

> 社区规则源已参考 [HyperModifier](https://github.com/AritxOnly/HyperModifier) 的默认规则，为 19 个应用预置了 `navBarVisibility`（如日历 / 相册 / 笔记等默认隐藏，QQ / 小红书等默认显示），可在可视化编辑器中随时调整。

## 规则注入

规则注入为模块核心机制（HyperOS 4.x），**默认自动启用，不提供界面开关**；HyperOS 3.3（3.0.3XX）由 App 侧以 Root 替换系统规则文件实现，效果等价（见上文「规则生效的整体链路」）。

### 模块规则覆盖合并

- **自动启用（HyperOS 4.x）**。
- **作用**：system_server 侧 Hook 在系统返回规则时，用模块规则按活动覆盖合并（模块优先），并强制启用、清空版本阈值。
- **意义**：这是「模块规则覆盖官方 cloudFeature」的核心，**不改写任何系统文件、不需要 Root**（3.3 上的文件挂载方式等价：写入前会保留官方 `.bak` 备份）；未配置到的应用 / 活动自动沿用官方规则。
- **注入范围**：注入载荷对**所有规则涉及的应用**生成，规则始终由 system_server 生效，**不需要把第三方应用加入 LSPosed 作用域**。

### 自动还原官方规则文件

- **自动启用（HyperOS 4.x）**。
- **作用**：旧版本 HyperNavBar 会直接覆盖系统规则文件并留下 `.bak`。此机制在 system_server 启动早期把 `.bak` 还原回目标文件、删除 `.bak` 与标记文件，让系统磁盘恢复为官方状态。
- **意义**：由于运行时由 Hook 注入规则，卸载模块后系统会**自动回到官方规则**，无需残留还原逻辑。

### 排除 Hook（hookExcluded）

- 模块格式规则支持在应用级别使用 `hookExcluded`，**默认 `true`**：默认不把模块注入第三方应用进程（不加入 LSPosed 作用域），**避免被应用检测到 Hook**。
- 该字段只控制系统是否把模块注入到**应用进程**，**不影响规则生效**——规则始终由 system_server 注入，对所有应用生效。
- 应用规则时按合并配置重写作用域：显式声明 `hookExcluded: false` 的应用会**自动申请加入作用域**（已在作用域或申请记录中的不重复申请）；不在规则列表中的应用（含仍为默认排除 `hookExcluded: true` 的）会被**自动移出作用域**。需要应用进程内取色（非全屏 / 分屏采样）时设为 `false` 即可，无需手动到 LSPosed 添加。
- 仅 **system（系统框架）** 始终保留在作用域中（模块本体依赖）；其余应用——包括系统应用——只要不在规则列表就会同样被移出。
- 在作用域页手动「排除」的应用（HookBlacklist）不会被自动申请，避免注入即闪退。
- 部分应用会检测 Xposed 注入并主动退出（即使不安装任何 Hook 也会崩，安全模式也无法避免），这类应用保持默认排除即可。
- 可视化编辑器在应用编辑面板中提供「排除 Hook」开关（默认开启），说明为「是否排除 Hook，Hook 相关特性将无法生效」。

## 模块

### 作用域

- 查看已被模块 Hook 的应用（图标 / 名称 / 版本 / 包名）。
- 对目标应用批量「重启」，使规则改动生效。
- **作用域由合并规则自动维护**：应用规则时，仅显式 `hookExcluded: false` 的应用会被自动加入作用域，已移出规则列表的应用会被自动移出；仅 system（系统框架）始终保留。
- 「取消申请的作用域」可一键移出模块历史上自动申请的应用，恢复为只保留 system。

### 安全模式

- **保护机制**：目标应用在加载 Hook 后短时间内反复崩溃时，自动跳过该应用的**全部 Hook**，避免系统应用反复崩溃导致无法开机。
- **手动控制**：可逐应用开关；关闭时恢复并清空崩溃计数。
- 关键应用（系统框架、系统界面、桌面、设置等）阈值更低，优先保护。

<br>

## 副作用与建议

- 「强制全屏语义」「忽略导航栏隐藏」侵入性最强，遇到分屏 / 全屏视频 / 游戏画面异常时优先关闭。
- 强制生效为**全局行为**，不区分单个应用；精细控制仍以「规则」页中针对具体应用 / 活动配置的 `style` 为主，强制生效只负责「让这些规则不被官方门槛拦住」。
- 修改任意开关或规则后，请**重启目标应用**再验证效果。
